## 3.1 RTSP Version

Current version: **RTSP/1.0**

Format:
```
RTSP-Version = "RTSP" "/" 1*DIGIT "." 1*DIGIT
```

Example:
```
RTSP/1.0
```

---

## 3.2 RTSP URL

### URL Schemes

| Scheme | Transport | Default Port |
|--------|-----------|--------------|
| `rtsp` | TCP | 554 |
| `rtspu` | UDP | 554 |

### URL Format

```
rtsp_URL = ( "rtsp:" / "rtspu:" ) "//" host [":" port] [abs_path]
```

### Examples

```
rtsp://media.example.com/twister/video
rtsp://media.example.com:8554/live/stream1
rtspu://192.168.1.100/test.mp4
rtsp://server.example.com/presentation/audio.en
rtsp://server.example.com/twister        (aggregate URL)
rtsp://server.example.com/twister/audio  (stream URL)
```

### URL Components

| Component | Required | Description |
|-----------|----------|-------------|
| scheme | Yes | `rtsp` or `rtspu` |
| host | Yes | Server hostname or IP |
| port | No | Default: 554 |
| abs_path | No | Resource path |

### Special Characters

The path component may include:
- Query string: `?key=value`
- Fragment (local use only): `#fragment`

URLs with `*` in Request-URI:
```
OPTIONS * RTSP/1.0
```
This requests server-wide options (not resource-specific).

## 3.3 Conference Identifiers

For joining existing conferences/sessions:

```
conference-id = 1*xchar
```

Used in the `Conference` header:
```
Conference: 128.16.64.19/32492374
```

Conference IDs are opaque to the protocol.

---

## 3.4 Session Identifiers

Session ID uniquely identifies an RTSP session. See [State Machines](A-state-machines.md) for session lifecycle.

```
session-id = 1*( ALPHA / DIGIT / safe )
safe       = "$" / "-" / "_" / "." / "+"
```

### Characteristics

- **Generated by**: Server (in first [SETUP](07-methods.md#104-setup) response)
- **Length**: SHOULD be at least 8 characters
- **Randomness**: SHOULD be cryptographically random (see [Security](14-security.md#session-id-security))
- **Scope**: Valid for duration of session

### Example

```
Session: 12345678
Session: A3D4F2B1C9E8
```

## 3.5 SMPTE Relative Timestamps

SMPTE (Society of Motion Picture and Television Engineers) timecodes:

### Format

```
smpte-range  = smpte-type "=" smpte-time "-" [smpte-time]
smpte-type   = "smpte" / "smpte-30-drop" / "smpte-25"
smpte-time   = 1*2DIGIT ":" 1*2DIGIT ":" 1*2DIGIT [":" 1*2DIGIT ["." 1*2DIGIT]]
```

### Structure

```
hours:minutes:seconds:frames.subframes
```

### Types

| Type | Frame Rate | Notes |
|------|------------|-------|
| `smpte` | 30 fps | 29.97 fps NTSC drop-frame |
| `smpte-30-drop` | 30 fps | Explicit drop-frame |
| `smpte-25` | 25 fps | PAL/SECAM |

### Examples

```
Range: smpte=0:10:20-0:20:30
Range: smpte=0:10:00:15-
Range: smpte-25=0:05:00-0:10:00
```

## 3.6 Normal Play Time (NPT)

NPT represents stream position relative to presentation start.

### Format

```
npt-range = "npt" "=" npt-time "-" [npt-time]
npt-time  = "now" / npt-sec / npt-hhmmss
npt-sec   = 1*DIGIT ["." 1*DIGIT]
npt-hhmmss = 1*DIGIT ":" 2DIGIT ":" 2DIGIT ["." 1*DIGIT]
```

### Time Formats

| Format | Example | Description |
|--------|---------|-------------|
| Seconds | `123.45` | 123.45 seconds from start |
| HH:MM:SS | `1:05:30.5` | 1 hour, 5 min, 30.5 sec |
| "now" | `now` | Current live position |

### Examples

```
Range: npt=0-               ; From start to end
Range: npt=10.5-20          ; 10.5s to 20s
Range: npt=1:05:00-         ; From 1h5m to end
Range: npt=now-             ; From current position (live)
Range: npt=0:0:0-0:10:35    ; First 10min 35sec
```

### Special Values

- **Beginning**: `npt=0-`
- **End**: `-npt=end` (seek to end)
- **Live position**: `npt=now-`

## 3.7 Absolute Time (UTC)

ISO 8601 timestamp format for absolute time synchronization.

### Format

```
utc-range = "clock" "=" utc-time "-" [utc-time]
utc-time  = utc-date "T" utc-time-val "Z"
utc-date  = 8DIGIT          ; YYYYMMDD
utc-time-val = 6DIGIT ["." fraction]  ; HHMMSS
```

### Examples

```
Range: clock=19961108T143720Z-
Range: clock=19961108T143720.25Z-19961108T153720Z
```

### Use Cases

- Scheduling recordings
- Synchronized playback across clients
- Time-shifting live content

## 3.8 Option Tags

Option tags identify protocol features/extensions.

### Format

```
option-tag = 1*xchar
```

### Registration

New option tags SHOULD be registered with IANA.

### Syntax Rules

| Character | Allowed |
|-----------|---------|
| alphanumeric | Yes |
| `-` | Yes |
| `.` | Yes |
| `!` `%` `*` `_` `+` `` ` `` `'` `~` | Yes |

### Usage in Headers

```
Require: implicit-play
Proxy-Require: gzipped-messages
Unsupported: implicit-play
```

### Example Option Tags

| Tag | Description |
|-----|-------------|
| `play.basic` | Basic playback |
| `setup.rtp.rtcp.mux` | RTP/RTCP multiplexing |
